The complete user guide

A short path to a running lab.

Start with Python 3.11+ and Git. The prerequisite installer checks for kind, kubectl and a container runtime, shows what’s missing, and asks before installing.

Clone. Check. Open.

From your terminal
git clone https://github.com/eco-ansible-content/awx-lab.git
cd awx-lab
./awx-lab prereq install
./awx-lab

No pip installation needed for the repository launcher. On macOS, install Homebrew first for package management.

Then type up.

The first build creates the cluster and deploys AWX. Opening the console alone doesn’t start anything.

When it’s ready, open the printed URL. Your username and password appear in the console and saved logs.

With pipx installed, run these commands from the AWX Lab clone: 

pipx install .

Open a new terminal if your PATH changed. The remaining examples use the installed command. Without installation, use the launcher’s absolute path when working in another checkout.

Pick the changes. Keep the lab.

Run awx-lab up first. Then select a source below. Each test updates AWX in the existing cluster and keeps the URL and database.

These examples use the installed awx-lab command. Install it with pipx first, or replace awx-lab with the absolute path to your repository launcher, such as /path/to/awx-lab/awx-lab. For local tests, run it from your AWX or plugin checkout.

Test before you commit.

Open your terminal in your AWX or awx-plugins checkout. Saved edits, staged changes and non-ignored new files are included. 

awx-lab test --local

# Require this branch to already be checked out:
awx-lab test --local my-feature

Your checkout and Git index stay unchanged. This snapshots one checkout; it doesn’t merge a target branch or combine local code with another PR.

Test an AWX pull request.

The PR is merged with its latest target branch in a managed checkout, then built and deployed. 

awx-lab test https://github.com/ansible/awx/pull/123

Replace the illustrative PR number with your open PR. Switching to AWX-only removes a previous custom plugin override.

Try a custom plugin.

Build the merged plugin PR into a wheel and install it into the lab’s baseline AWX image. The checks verify the installed wheel hash. 

awx-lab test https://github.com/ansible/awx-plugins/pull/456

# Optionally select a different baseline AWX ref:
awx-lab test https://github.com/ansible/awx-plugins/pull/456 \
  --awx-ref devel

Replace the illustrative PR number with your open PR. Use your own credentials and data for feature testing in AWX.

AWX and plugin changes, together.

Each PR is merged with its own latest target branch. The plugin wheel is installed in the AWX PR image. 

awx-lab test https://github.com/ansible/awx/pull/123 \
  --plugins-pr https://github.com/ansible/awx-plugins/pull/456

Replace both illustrative PR numbers. Two PRs are supported in this combination; two local checkouts are not.

--suite jobAdd a real Ansible localhost ping job.

--no-cacheForce a fresh AWX/UI build for this test.

Stop for today.
Keep your work for tomorrow.

awx-lab down

Stop the lab’s nodes. Keep the database, images and managed files. Run up to resume.

awx-lab down --purge

Destroy this lab, its database, tracked images and managed files. Shared caches and the runtime VM remain.

Tests reuse the cluster and caches. Changed sources rebuild; unchanged sources reuse the image and rerun checks. Recent image pairs, reports and logs have bounded retention; shared caches and the database can still grow.

Migrations can modify retained data. Failed updates don’t roll back automatically. Storage and retention details

Update AWX Lab without recreating the environment

From the AWX Lab clone:

git pull --ff-only
# If you installed from this clone with pipx:
pipx reinstall awx-lab

The repository launcher uses updated code immediately. CLI updates preserve your lab and data.

The command bench.

A quick reference for daily work. For every option and configuration default, open the full command reference.

Command Purpose
awx-lab Open the console and live logs.
awx-lab doctor Check tools, runtime connectivity and resources.
awx-lab prereq install Review, approve and install missing prerequisites.
awx-lab plan [PR_URL] Read-only preview of setup or a PR test.
awx-lab up Create or resume the environment.
awx-lab test <PR_URL> Build and test an AWX or plugin PR; combine with --plugins-pr.
awx-lab test --local [BRANCH] Test saved changes from the current source checkout.
awx-lab status Show saved state; this is not a live health check.
awx-lab credentials Retrieve the running lab’s URL, username and password.
awx-lab logs [--follow] Read or follow detailed logs.
awx-lab down [--purge] Stop and retain the lab, or destroy it with --purge.
awx-lab --help Show help; add --help after any command for its options.
awx-lab --version Print the installed version.

No commands match. Try “test”, “logs” or “down”.

Global --state-dir PATH goes before the command. The default is ~/.local/share/awx-lab/runs. Environment variables and state
